# AI-ассистент медицинской регистратуры

Текстовый ассистент, который помогает пациенту записаться к врачу.
Общение — через CLI. Ассистент на базе локальной LLM (Ollama + Qwen3:8b).

## Как запустить

### 1. Предварительно

- Установлен [Ollama](https://ollama.com)
- Скачана модель: `ollama pull qwen3:8b`
- Есть токен команды от организаторов (Bearer)

### 2. Установка

```bash
python -m venv .venv

# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

### 3. Настройка

Скопируй `.env.example` в `.env` и впиши свой токен:

### 4. Загрузить расписание в SQLite

```bash
python -m app.schedule.loader
```

Ожидаемый вывод:

```
Загружено слотов: 180
Загружено длительностей: 30
```

### 5. Запустить ассистента

```bash
python -m app.main
```

Для выхода — `выход` или `Ctrl+C`.

## Что реализовано

- Регистрация клиента в CRM (POST /clients)
- Поиск врачей по специальности (GET /doctors)
- Свободные слоты врача на дату: расписание из SQLite минус занятые слоты из CRM
- Запись на приём (POST /visits)
- Список записей клиента (GET /visits)
- Отмена записи (PATCH /visits/{id}, status=«Отменена»)
- Агент сам вызывает инструменты по ходу диалога (Ollama function calling)
- Длительность приёма берётся из xlsx (20 или 30 мин)

## Ограничения и допущения

- Mock CRM не хранит расписание и не проверяет занятость. Поэтому занятость слотов проверяется на нашей стороне: расписание из xlsx + уже созданные записи через `GET /visits`. Это осознанное решение.
- Часовой пояс стенда — GMT+4. Все даты в диалоге интерпретируются в этом поясе.
- Диалог хранится в памяти процесса. После перезапуска история теряется.
- Один пользователь на процесс. CLI не рассчитан на многопользовательский режим.
